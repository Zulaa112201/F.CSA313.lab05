Энэ лабораторид "хичээлд бүртгүүлэх" API-г локал дээр ажиллуулж, `POST /registrations` функцийг Лекц 5-ын тест дизайны 5 алхмаар тестлэсэн. Тестүүдийг Postman дээр бичиж, Newman-аар командын мөрөөс автоматаар ажиллуулсан.

## 1. Орчин

```bash
node -v     # v22.14.0
newman -v   # 6.2.3
```

API серверийг `node server.js` гэж асаахад `http://localhost:3000` дээр ажиллана. Collection дотор энэ хаяг `baseUrl` хувьсагчаар тохируулагдсан.

Репогийн бүтэц:

```text
server.js                    тестлэгдэх API
lab05-collection.json       үндсэн collection (PASS)
lab05-collection-fail.json  нэг oracle-ийг зориуд буруу болгосон хуулбар (FAIL)
results/
  newman-pass.txt
  newman-fail.txt
  newman-down.txt
README.md
```

## 2. Тест дизайн

Тестлэх функц нь `POST /registrations`, хүсэлтийн бие нь `{"studentID": "...", "courseID": "..."}`.

### Сонголт ба төлөөлөх утгууд

| № | Сонголт | Эквивалент анги | Төлөөлөх утга |
| :-: | :--- | :--- | :--- |
| 1 | studentID-гийн хүчинтэй байдал | Идэвхтэй оюутан (`status="active"`) | `T01_S`, `T04_S`, `T05_S`, `T06_S`, `T07_S` |
| | | Идэвхгүй оюутан (`status="inactive"`) | `T03_S`, `T08_S`, `T10_S` |
| | | Байхгүй оюутан (PUT хийгээгүй) | `T02_NOSUCH`, `T09_NOSUCH` |
| 2 | Оюутны үзсэн хичээлүүд | Урьдач нөхцөлийг бүрэн хангана | `coursesTaken=["CS201"]` (`T01_S`) |
| | | Урьдач нөхцөлийг хэсэгчлэн хангана | `coursesTaken=["CS201"]` (`T06_S`) |
| | | Урьдач нөхцөлийг огт хангахгүй | `coursesTaken=[]` (`T05_S`) |
| 3 | courseID-гийн хүчинтэй байдал | Хичээл байгаа | `T01_C`, `T02_C`, `T03_C`, `T05_C`, `T06_C`, `T07_C`, `T10_C` |
| | | Хичээл байхгүй (PUT хийгээгүй) | `T04_NOSUCH`, `T08_NOSUCH`, `T09_NOSUCH` |
| 4 | Хичээлийн урьдач нөхцөл | Урьдач нөхцөлгүй | `T07_C`: `prerequisites=[]` |
| | | Бүгдийг нь үзсэн байхыг шаардана | `T01_C`: `["CS201"]` |
| | | Олон хичээл шаардана, зарим нь дутуу | `T06_C`: `["CS201","CS202"]` |
| | | Огт үзээгүй байхыг шаардана | `T05_C`: `["CS201"]` |
| 5 | Хүсэлтийн формат | Хоёр талбар бүгд байна | `{"studentID","courseID"}` |
| | | courseID дутуу | `{"studentID":"T11_S"}` |
| | | studentID дутуу | `{"courseID":"T12_C"}` |
| | | Буруу JSON | `{"studentID": "T13_S", ` |

**Боломжгүй хослолууд.** Байхгүй оюутанд `status` гэж байхгүй тул "байхгүй оюутан + идэвхгүй" гэсэн хослол байж болохгүй. Мөн оюутан эсвэл хичээл байхгүй бол урьдач нөхцөлийг үнэлэх юм алга, тиймээс эдгээрийг тусад нь тест болгоогүй.

**Давхар алдааны дараалал.** Зааварт нэг хүсэлтэд хэд хэдэн алдаа зэрэг гарвал аль нь буцахыг бичээгүй, тиймээс T08–T10-аар өөрөө тогтоосон. Идэвхгүй оюутан байхгүй хичээлтэй эсвэл урьдач дутуутай зэрэг ирсэн ч `ERROR_INACTIVE_STUDENT` гарна. Байхгүй оюутан байхгүй хичээлтэй ирвэл `ERROR_NO_STUDENT` гарна. Үүнээс шалгалтын дараалал нь NO_STUDENT, INACTIVE_STUDENT, NO_COURSE, PREREQUISITES гэж харагдаж байна.

### Спецификацийн хүснэгт

| № | Спецификац | Төрөл | Оролт (studentID / courseID) | Setup | Статус | Хүлээгдэх result |
| :-: | :--- | :--- | :--- | :--- | :-: | :--- |
| T01 | Happy path | Happy path | `T01_S` / `T01_C` | T01_S: active, `["CS201"]`; T01_C: `["CS201"]` | 201 | `OK`, registrationID тоо |
| T02 | Байхгүй оюутан | Алдааны анги | `T02_NOSUCH` / `T02_C` | T02_C: `[]` | 200 | `ERROR_NO_STUDENT` |
| T03 | Идэвхгүй оюутан | Алдааны анги | `T03_S` / `T03_C` | T03_S: inactive, `["CS201"]`; T03_C: `["CS201"]` | 200 | `ERROR_INACTIVE_STUDENT` |
| T04 | Байхгүй хичээл | Алдааны анги | `T04_S` / `T04_NOSUCH` | T04_S: active, `[]` | 200 | `ERROR_NO_COURSE` |
| T05 | Урьдач огт хангаагүй | Алдааны анги | `T05_S` / `T05_C` | T05_S: active, `[]`; T05_C: `["CS201"]` | 200 | `ERROR_PREREQUISITES`, missing=`["CS201"]` |
| T06 | Урьдач зарим нь дутуу | Алдааны анги | `T06_S` / `T06_C` | T06_S: active, `["CS201"]`; T06_C: `["CS201","CS202"]` | 200 | `ERROR_PREREQUISITES`, missing=`["CS202"]` |
| T07 | Урьдачгүй хичээл, хоосон coursesTaken | Хязгаар | `T07_S` / `T07_C` | T07_S: active, `[]`; T07_C: `[]` | 201 | `OK` |
| T08 | Идэвхгүй оюутан + байхгүй хичээл | Давхар алдаа | `T08_S` / `T08_NOSUCH` | T08_S: inactive, `[]` | 200 | `ERROR_INACTIVE_STUDENT` |
| T09 | Байхгүй оюутан + байхгүй хичээл | Давхар алдаа | `T09_NOSUCH` / `T09_NOSUCH` | байхгүй | 200 | `ERROR_NO_STUDENT` |
| T10 | Идэвхгүй оюутан + урьдач дутуу | Давхар алдаа | `T10_S` / `T10_C` | T10_S: inactive, `[]`; T10_C: `["CS201"]` | 200 | `ERROR_INACTIVE_STUDENT` |
| T11 | courseID дутуу | Хязгаар | `T11_S` / (courseID байхгүй) | байхгүй | 400 | `ERROR_BAD_REQUEST` |
| T12 | studentID дутуу | Хязгаар | (studentID байхгүй) / `T12_C` | байхгүй | 400 | `ERROR_BAD_REQUEST` |
| T13 | Буруу JSON | Хязгаар | эвдэрсэн JSON бие | байхгүй | 400 | `ERROR_BAD_JSON` |

## 3. Collection

Тест бүр collection дотор өөрийн folder-той (T01–T13), folder дотор нь setup PUT хүсэлтүүд, дараа нь `POST /registrations` байна. Нийт 15 setup PUT, 13 POST, нийт 28 request. Тест бүр өөрийн ID-тай (`T01_S`, `T01_C` гэх мэт) тул бусад тестээс хамаарахгүй, дарааллыг нь сольж болно.

Oracle нь ихэнх тест дээр хоёр түвшинтэй: эхлээд статус код, дараа нь `result` утга. T05, T06 дээр нэмж `missing` массивыг, T01 дээр registrationID тоо мөн эсэхийг шалгана. Сервер ажиллах бүрд registrationID өсөөд байдаг тул яг утгыг нь шалгаагүй, зөвхөн `number` төрөлтэй эсэхийг л шалгасан.

Нийт 13 тест, 29 assertion байна (T01, T05, T06 тус бүр 3, бусад 10 нь тус бүр 2).

## 4. Newman-аар ажиллуулсан үр дүн

```bash
mkdir -p results
newman run lab05-collection.json 2>&1 | tee results/newman-pass.txt
echo "exit=${PIPESTATUS[0]}"
```

`tee`-ийн дараа `$?` бичвэл tee-ийн 0-г авдаг тул exit code-ийг `${PIPESTATUS[0]}`-оор авсан. FAIL болон DOWN ажиллуулалтыг мөн ижил аргаар хийсэн (файлын нэр л өөр). Гурван ажиллуулалтын бүтэн гаралт `results/` хавтсанд бий.

| Ажиллуулалт | Файл | requests (executed / failed) | assertions (executed / failed) | Exit code |
| :--- | :--- | :---: | :---: | :---: |
| PASS | `results/newman-pass.txt` | 28 / 0 | 29 / 0 | 0 |
| FAIL | `results/newman-fail.txt` | 28 / 0 | 29 / 1 | 1 |
| DOWN | `results/newman-down.txt` | 28 / 28 | 29 / 29 | 1 |

### PASS

Бүх 29 assertion давсан, failed 0, exit code 0. Дундаж хариу 3ms байсан. README дээрх 29 гэсэн тоо `newman-pass.txt`-ийн `assertions executed` мөртэй таарна.

### FAIL

`lab05-collection-fail.json` нь үндсэн collection-ий хуулбар. Зөвхөн T01-ийн статусын oracle-ийг 201-ийн оронд 200 гэж зориуд буруу болгосон. Үр дүнд Newman дараах алдааг гаргаж, exit code 1 буцаасан:

```text
1.  AssertionError  Статус 201
                    expected response to have status code 200 but got 201
                    at assertion:0 in test-script
                    inside "T01 Happy path: ... / Идэвхтэй оюутан, урьдач хангасан үед OK"
```

Төгсгөлийн хүснэгтэд requests 28 / failed 0, assertions 29 / failed 1 гэж гарсан. Алдаа яг нэг assertion дээр гарсан, T01-ийн бусад хоёр assertion болон үлдсэн 12 тест хэвээр давсан. Тестийн нэр "Статус 201" хэвээр үлдсэн ч код нь 200-г хүлээж байгаа. Үндсэн `lab05-collection.json` өөрчлөгдөөгүй, зөв хэвээр байгаа. Энэ нь CI-д quality gate хэрхэн ажилладгийн жишээ: нэг oracle унахад exit code 0 биш болж, pipeline зогсоно.

### DOWN

Серверийг Ctrl+C-ээр унтраагаад ажиллуулахад 28 request бүгд `connect ECONNREFUSED 127.0.0.1:3000` алдаатай унасан. Хариу ирээгүй учир 13 test-script ажилласан ч 29 assertion бүгд унасан (`expected PostmanResponse to have property 'code'`, `"undefined" is not valid JSON`). Нийт 0B өгөгдөл хүлээн авсан. Энэ бол интерфейсийн алдаа, өөрөөр хэлбэл сервертэй холбогдож чадаагүй. FAIL-ийн үед сервер хариу өгсөн ч хариу нь oracle-ийн хүлээлттэй таарахгүй байсан бол энд хариу огт ирээгүй, тиймээс oracle-ийг үнэлэх юм байгаагүй.

## 5. Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодох хэрэгтэй болсон нь сонголтуудыг эквивалент ангид хуваах алхам байлаа. Оюутны төлөв, үзсэн хичээл, хичээлийн урьдач гурав хоорондоо уялдаатай тул "урьдач хангана" гэдгийг оюутан талаас ч, хичээл талаас ч нь нэг дор тодорхойлох хэрэгтэй болсон. Хослолуудыг гаргаж үзэхэд зарим нь боломжгүй байсан: байхгүй оюутанд `status` байхгүй тул "байхгүй оюутан + идэвхгүй" гэж байж болохгүй, оюутан эсвэл хичээл байхгүй бол урьдачийг үнэлэх ч боломжгүй. Давхар алдаанд аль нь түрүүлж буцахыг зааварт бичээгүй тул T08–T10 тестээр өөрөө шалгаж тогтоосон. Идэвхгүй оюутан бусад алдаатай зэрэг ирвэл `ERROR_INACTIVE_STUDENT`, байхгүй оюутан бол `ERROR_NO_STUDENT` түрүүлж гардаг нь тэндээс харагдсан. Миний бичсэн тестүүд API дээр ямар ч согог илрүүлээгүй, 29 assertion бүгд давсан. Харин FAIL ажиллуулалт хамгийн сургамжтай байсан, учир нь нэг хүлээлтийг л буруу болгоход exit code 1 болж, автомат шалгалт алдааг шууд барьж байгааг харсан. DOWN ажиллуулалтаар сервер унтарсан үеийн `ECONNREFUSED` нь oracle унасан хэрэг биш, холболтын алдаа гэдгийг ялгаж ойлгосон. Тест бүр өөрийн setup-тай бие даасан тул дарааллаас хамаарахгүй, мөн registrationID-ийн утгыг биш төрлийг нь шалгадаг учраас давтан ажиллуулахад тогтвортой байна.
